## سه تصمیم و دلیلشان

### ۱. `apps/desktop` حذف شد — یک محصول جدا، نه یک سطح از این محصول

Electron shell برای macOS و Windows. تنها ارجاع‌هایش دو workflow بودند که هر دو حذف یا اصلاح شدند. هیچ کد پایتونی، هیچ مسیری در API، و هیچ بخشی از وب اپ به آن وابسته نبود. حذفش چیزی از محصول وب کم نمی‌کند.

### ۲. `packages/chat-engine` **نگه داشته شد** — این دسکتاپ نیست

وسوسه‌اش زیاد بود: نامش «engine» است و در `packages/` نشسته. ولی ممیزی نشان داد `deeptutor/runtime/ts_engine/client.py` یک child process از `packages/chat-engine/dist` بالا می‌آورد، و `agents/loop/` و `capabilities/explore_context/` و `typescript_provider` از آن استفاده می‌کنند.

با `DEEPTUTOR_CHAT_ENGINE=python` (پیش‌فرض) این مسیر خاموش است — پس **در عمل** کد مرده است. ولی حذفش یعنی حذف یک موتور چت جایگزین برای **همین وب اپ**، نه حذف یک سطح غیروب. تفاوت این دو، همان تفاوتی است که درخواست شما بر آن استوار بود. اگر قرار است این هم برود، یک تصمیم جدا لازم دارد، نه یک حذف جانبی.

### ۳. CLI به یک لانچر باریک کاهش پیدا کرد، حذف نشد

این نکتهٔ اصلی است و باید صریح گفته شود: **`deeptutor start` همان چیزی است که وب اپ را بالا می‌آورد.** README خط ۳۰۰، `Dockerfile`، و `deeptutor/runtime/launcher.py:1318` همه از `deeptutor_cli.main start` استفاده می‌کنند. اگر CLI کامل حذف می‌شد، وب اپ راهی برای بالا آمدن نداشت.

پس CLI حذف نشد، **تفکیک شد**:

- **می‌ماند:** `main.py` (کاهش‌یافته)، `init_cmd`, `init_wizard`, `setup_config`, `doctor`, `module`, `common` (فقط بخش‌های لازم برای لانچر).
- **می‌رود:** `chat`, `skill`, `plugin`, `config_cmd`, `session_cmd`, `provider_cmd`, `workspace_cmd`, `kb`, `notebook`, `book`, `partner`, `memory`, `skill_login`, `skill_prompts`, `_tool_result`.

`init` و `doctor` می‌مانند چون اولین اجرا و تشخیص خرابی، بخشی از تجربهٔ راه‌اندازی وب هستند. `init_wizard` هم برای همان.

## سه اشتباه که خودم مرتکب شدم و آزمون‌ها گرفتند

این‌ها را ثبت می‌کنم چون حذف بی‌دقت همین‌طوری آسیب می‌زند:

۱. **`maybe_run` را با یک context manager بی‌ربط جایگزین کردم.** نسخهٔ اصلی `close_application_container` را صدا می‌زد تا leaseها آزاد شوند. `test_runtime_cleanup` گرفت. پیاده‌سازی اصلی بازگردانده شد.

۲. **`serve` را بیش از حد کوتاه کردم** و `proxy_headers`, `ws_max_size`, `timeout_keep_alive` را انداختم. این سه، همان چیزی‌اند که از خطای `ECONNRESET` → ۵۰۰ → «Failed to load sessions» جلوگیری می‌کنند. `test_uvicorn_launch_flags` گرفت. هر سه بازگردانده شدند.

۳. **`apply_file`/`runner` را در آزمون جدید جا انداختم** و `pyflakes`/اجرا گرفت — پیش از کامیت رفع شد.

**درس:** حذف کد مشکلی ندارد؛ حذف کدِ *نخوانده* مشکل دارد. هر سه مورد بالا از توابعی بود که به‌نظر «تزئینی» می‌آمدند و نبودند.
